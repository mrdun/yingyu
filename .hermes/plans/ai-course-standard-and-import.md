## 一、AI 建课：现状到底做了什么

### 1.1 入口（后台「课程中心 → AI 建课」一页，4 个 tab）

页面 `apps/admin/pages/courses/ai.vue`，接口 `apps/api/src/ai-content/ai-content.controller.ts`：

| tab        | 接口                           | 落库?     | 说明                                |
| ---------- | ------------------------------ | --------- | ----------------------------------- |
| 文本拆句   | `POST /ai-content/split`       | ❌ 仅预览 | 只切句，给运营看一眼结果            |
| 文本建课包 | `POST /ai-content/course-pack` | ✅        | 一段文本 → 切句 → 建课包            |
| 字幕建课包 | `POST /ai-content/subtitle`    | ✅        | 上传的是**字幕文本**，解析后同上    |
| 音频建课包 | `POST /ai-content/audio`       | ✅        | 音频转 base64 → Whisper 转写 → 同上 |

### 1.2 建课时**写死了**这些（`ai-content.service.ts` 的 `createCoursePack`）

| 字段                    | 固定值                             | 意味着                                            |
| ----------------------- | ---------------------------------- | ------------------------------------------------- |
| `status`                | `draft`                            | 建出来**一定不进前台**，必须走「提交审核 → 发布」 |
| `source`                | `ai`                               | 后台详情页据此显示「AI 生成」提醒                 |
| `accessLevel`           | `membership`                       | 默认会员课                                        |
| `isFree` / `shareLevel` | `false` / `private`                | 默认不免费、不公开                                |
| 每课句数                | **10 句**（`DEFAULT_COURSE_SIZE`） | 200 句的文本 → 20 门「第 N 课」                   |

### 1.3 产出**只有 4 个字段**

`order` / `chinese` / `english` / `soundmark` —— 句子的最小集合。
**没有**：语法标注、难度、学习目标、场景标签、课程级元数据。

### 1.4 一次建课要调几次 AI

- 切句：**1 次**
- 语法标注：**每 10 句 1 次**（200 句 → +20 次），**并发 3 批**，任一批失败只丢那批的标注
  （已落地并端到端实测：见 §1.5）

### 1.5 语法标注已接进管道（2026-09-15 实测通过）

| 项       | 状态                                                                                            |
| -------- | ----------------------------------------------------------------------------------------------- |
| 标注能力 | `apps/api/src/ai-content/grammar-annotation.ts`（位置由程序算 / 结构式由程序映射 / 每批 10 条） |
| 写库     | `statements.grammar`，**库里必须是 jsonb object**（见下方两个坑）                               |
| 容错     | 取模型失败 / 返回垃圾 / 单条不合规 → 只丢标注，**建课照常**（有测试钉住）                       |
| 端到端   | 真实调 DeepSeek 建一门测试课：**9/9 句标注成功**，结构式正确，106 条偏移零错，测试数据已清      |
| 测试     | API 全量 **63 套件 / 539 用例** 全过                                                            |

**过程中查出并修掉的两个真 bug（都只有真实跑一遍才会暴露）：**

1. **jsonb 被双编码**：直接把对象交给 drizzle 的 `jsonb()` 列 → 驱动把「JSON 字符串」当 jsonb **值**
   再包一层 → 库里是 `jsonb_typeof='string'`。症状很隐蔽：**ORM 读回来照样正常**，
   但 `grammar->>'structure'`、后台统计、导出**全部取不到东西**。
   → 改为自定义列类型，把值原样交给驱动（insert 的契约不变）。
2. **模型会删句末标点**：给 `I like the food.` 做标注时，模型输出的 words 里句号没了
   → 校验器（正确地）判为「拼不回原文」→ **整句标注被丢弃**。
   现有语料无标点所以没暴露，但**字幕/音频入口的文本会带标点**。
   → 提示词补「KEEP the punctuation」，并加两条守卫：提示词的**两份副本必须逐字一致**、
   必须含该要求。

## 二、「AI 生成课程的标准」——现在有两层，只落地了一层

### 第一层：数据结构标准（产出必须长什么样）→ **有规范，接口只落了 1/3**

规范文件：**`COURSE_CREATION_FORMAT.md`（v1.7）**，内容包括：

- `formatVersion` 版本号、`courses[]` / `statements[]` 结构
- **语法标注完整定义**：`isSentence` / `words[]`(逐词词性) / `phrases[]`(成分) /
  `pattern`(闭集符号) / `structure`(程序映射) / `clauseType` / `tense` / `keyPoints`
- **13 条硬校验（E1–E13）+ 6 条告警（W1–W6）**
- §10 排版约束（胶囊视觉语言、长句从句断行、色板对比度）

| 规范里的要求                               | 接口现状                                                          |
| ------------------------------------------ | ----------------------------------------------------------------- |
| 句子基本字段（中/英/音标）                 | ✅ 已产出                                                         |
| **语法标注**                               | ⚠️ 本次刚接（每 10 句一批，程序算位置与结构式）                   |
| `formatVersion` / 文件级格式（可导入导出） | ❌ 只有脚本在读写，**接口不产出这个文件格式**                     |
| 全量校验（E1–E13）                         | ❌ 接口只在写库前做**轻量**校验；完整校验器目前只在 Python 脚本里 |

**结论**：规范是「课程文件」的标准，接口是「在线建课」的标准，两者**没有对齐**。
现在接口相当于规范的一个子集。

### 第二层：内容标准（这门课教得怎么样）→ **完全没有，建议补**

目前**没有任何规则**约束 AI 生成的课内容质量。可量化的现状（全库 55 课实测）：

| 指标           | 全库实测                                          | AI 建课现状 |
| -------------- | ------------------------------------------------- | ----------- |
| 每课句数       | 平均 161（最长 566，最短若干）                    | 固定 10     |
| 句长           | 中位 19 字符 / 3.7 词；最长 119 字符 / 23 词      | 无限制      |
| 碎片 vs 完整句 | 第一课 118 碎片 / 100 完整句（46% 是 1–2 词碎片） | 无概念      |
| 难度梯度       | 一课内「碎片渐进 → 完整句」                       | 无          |

**建议补的内容标准（都用实测数字支撑，不是拍脑袋）**：

1. **句长软上限 50 字符 / 9 词** —— 保住 94.8% 的现有内容，且这批在现有面板宽下 99.6% 不折行。
   **作为提示词偏好，不设为校验错误**（设成错误会否决大量合法长句）。
2. **一课内碎片比例**：前 1/3 放碎片、中间放短句、后 1/3 放完整句（照第一课的成功结构）。
3. **每课句数**：AI 建课默认 10 句一门偏少（第一课 218 句）—— 建议建课时允许指定，
   或默认按 30 句/课。
4. **句子去重**：同一课包内不得出现重复 `english`（全库 8,865 句里有 4,753 条唯一，
   重复率 46% → 现有内容里大量重复，AI 生成时应避免）。

## 三、第三方课程导入：现状与缺口

### 3.1 已经有的（可复用的基础件）

| 能力           | 位置                                                 | 说明                         |
| -------------- | ---------------------------------------------------- | ---------------------------- |
| 建空课程包     | `POST /admin/course-packs`                           | 手工建                       |
| 建课           | `POST /admin/course-packs/:id/courses`               | 手工建                       |
| **建单条句子** | `POST /admin/courses/:courseId/statements`           | ⚠️ **一次只能一条**          |
| 状态流转       | submit-review / publish / reject / archive / restore | 完整                         |
| 改权限/免费    | `access-level` / `toggle-free`                       | 完整                         |
| **音频上传**   | `POST /ai-content/audio`（base64）                   | 这是全仓**唯一**像上传的东西 |
| 语法标注格式   | `COURSE_CREATION_FORMAT.md` + `validate-format.py`   | 可当导入格式规范与校验器     |

### 3.2 明确缺的（四块，缺一不可）

| 缺口                   | 现状证据                                                                                                                          | 说明                                                   |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| **① 文件上传**         | 全仓搜 `multer` / `FileInterceptor` / `UploadedFile` → **零命中**（只有音频走 base64）                                            | 收不到文件就无从导入                                   |
| **② 解析器**           | `course_packs.source` 注释里**预留了 `import`**，但全仓搜 `'import'` 实现 → **零命中**                                            | 第三方格式 → 我们的格式                                |
| **③ 批量写入**         | `CreateStatementDto` 是**单条**；200 句就是 200 次请求                                                                            | 必须做成一个事务批量写                                 |
| **④ 预览 + 校验报告**  | 无                                                                                                                                | 哪几条不合格、为什么，运营要看得见                     |
| **⑤ 后台「来源」标签** | `apps/admin/utils/courseStatus.ts` 的 `COURSE_PACK_SOURCE` **只认 `manual` / `ai`**（未知名会走 `presentUnknown` 兜底展示原始值） | 导入的课要在后台一眼看出是「第三方导入」，得加一个标签 |

### 3.2.1 现状数据（RC 库实测）

`SELECT source, count(*) FROM course_packs GROUP BY source` → **只有 1 条，`manual`**。
即：`ai` / `subtitle` / `audio` / `import` 目前**库里都没有实际数据**（AI 建课建成后是 draft，
可能已被清理或从没真正建过正式课）。导入功能属于**从 0 开始**，不用考虑历史数据兼容。

### 3.3 关键判断：**格式规范已经就位，导入缺的只是「通道」**

这是好消息。`COURSE_CREATION_FORMAT.md` 就是为「外部制作好的课程进来」设计的：

- 它定义了**文件级格式**（`formatVersion` + `courses[]` + `statements[]`）
- 它带**完整的校验规则**（E1–E13），且有**可跑的校验器**（`scripts/grammar/validate-format.py`）
- 它的语法标注口径与前台渲染**已经对齐**（本次已接进练习页）

所以导入不需要重新设计格式 —— 需要的是：**上传 → 用现成校验器验 → 批量事务写 → 给运营看报告**。

### 3.4 三个方案（各有取舍，需拍板）

| 方案                             | 做法                                                                                                           | 优点                                                                 | 缺点                                                     | 工作量     |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- | -------------------------------------------------------- | ---------- |
| **A. 只收 JSON（推荐起步）**     | 后台加一个「导入课程」页：上传/粘贴 `COURSE_CREATION_FORMAT.md` 格式的 JSON → 校验 → 批量建课（draft）→ 出报告 | 格式与校验器都已存在，**改动最小**；第三方工具只要按格式导出就能进来 | 第三方得改成我们的格式（但规范是公开的）                 | 中         |
| **B. 支持常见表格（CSV/Excel）** | 除了 JSON 还能收 CSV/Excel（列：英文、中文、音标、可选标注列）                                                 | 运营/第三方最容易产出；非技术人也能做课                              | 语法标注（成分/词性）表格表达很别扭；要写映射与容错      | 中偏大     |
| **C. 直接对接第三方工具**        | 为具体工具（如某字幕/课件工具）写专用适配器                                                                    | 最省对方的事                                                         | **强绑定单一工具**；对方改版就坏；现在没有确定的目标工具 | 大且不通用 |

**推荐：先 A，再按需加 B。** 理由：A 能把「格式规范 + 校验器 + 批量写」这条主链路一次打通，
且与本项目的语法标注体系天然一致；B 是在 A 之上的输入友好层，等真有第三方提 CSV 需求再加。

### 3.5 导入必须遵守的两条（与 AI 建课保持一致）

1. **一律进 draft**：导入的课不能直接可见，必须走「提交审核 → 发布」（与 AI 建课同规格）。
2. **标注不合规的句子要能选**：E 类错误（数据不合规）按规范该**整句不显示**，
   导入时应给运营两个选项：**整份拒绝** 或 **跳过坏句子 + 报告清单**。推荐后者（附报告）。

## 四、决策点（✅ 已拍板 2026-09-15）

| #   | 问题                                                       | 决定                                                                       | 落地位置（待做）                                                  |
| --- | ---------------------------------------------------------- | -------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| 1   | AI 建课要不要加**内容标准**（句长/碎片比例/每课句数/去重） | ✅ **加**，先只加「句长软上限 + 同课包去重」两项（写进提示词，不做硬校验） | `apps/api/src/ai-content/ai-content.service.ts` 的 `SPLIT_PROMPT` |
| 2   | 每课句数默认值                                             | ✅ **建课时可填，默认 30**（原为写死 10）                                  | `CoursePackDto.courseSize` 默认值 + 后台建课表单                  |
| 3   | 导入格式先支持哪种                                         | ✅ **先 JSON**（`COURSE_CREATION_FORMAT.md` 格式），后续按需加 CSV/Excel   | 后台新增「导入课程」页 + `POST /admin/course-packs/import`        |
| 4   | 导入时遇到坏句子                                           | ✅ **跳过 + 报告**（不整份拒绝）                                           | 导入返回值带 `skipped[]`（含原因），后台列出                      |
| 5   | 导入的课归属                                               | ✅ **不能直接可见**：进 draft → 提交审核 → 发布（与 AI 建课一致）          | 导入时写 `status=draft`、`source=import`；后台来源标签补 `import` |

由 #1 推导的细则（与实测数据一致）：

- 句长**软上限 50 字符 / 9 词**（保住 94.8% 现有内容，其中 99.6% 不折行）；
- 同课包内 `english` **不得重复**（现有内容重复率 46%，新生成应避免）。

**实施顺序**：#1、#2 是同一处改动（AI 建课提示词 + DTO 默认值），可一起做；
#3–#5 是导入功能的三个面，属独立一批。
