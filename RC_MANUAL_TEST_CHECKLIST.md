# RC 人工测试 Checklist (TASK-002-L-01)

> 目的: 在本地「生产模式」RC 环境上, 由人工按真实用户路径验收 MVP。
> 自动化已覆盖的部分见 `RC_VALIDATION_REPORT.md`; 本清单只列**必须人工点过**的项目。

---

## 0. 启动 RC 环境 (每次测试前)

```bash
# 0.1 基础设施 (PostgreSQL 5480 / Redis 6379 / Logto 3010)
docker compose up -d db testdb redis testRedis logto logtoPostgres

# 0.2 准备 RC 数据库 (独立库 earthworm_rc, 不影响 dev/test 库)
cp apps/api/.env.rc.example apps/api/.env.rc     # 填写本机 Logto 凭据
pwsh scripts/rc-local-prod.ps1 -Action reset      # 重建库 + migration + 内容 seed

# 0.3 生产构建
pwsh scripts/rc-local-prod.ps1 -Action build      # 后端 (nest build)
pnpm build:client                                 # 前端 (nuxt generate, 需生产/RC 变量)

# 0.4 启动
pwsh scripts/rc-local-prod.ps1 -Action start      # 后端: NODE_ENV=prod, 端口 3001
node scripts/rc-static-server.mjs                 # 前端: http://127.0.0.1:4173

# 0.5 冒烟 (必须全绿)
pnpm smoke:prod -- --base=http://127.0.0.1:3001
```

环境地址: 前端 <http://127.0.0.1:4173> · API <http://127.0.0.1:3001> ·
Logto <http://localhost:3010> · 健康检查 <http://127.0.0.1:3001/health>

> ⚠️ RC 使用**占位支付凭据**, 不会发起真实网关请求。支付/退款的真实链路验收在
> `PAYMENT_MERCHANT_INTEGRATION_CHECKLIST.md` 的商户环境执行。

## 1. 用户主链路 (游客 → 会员 → 学习)

| #   | 步骤                    | 操作                                                 | 预期                                                                                       | 通过 |
| --- | ----------------------- | ---------------------------------------------------- | ------------------------------------------------------------------------------------------ | ---- |
| U1  | 游客访问首页            | 打开 `http://127.0.0.1:4173/`                        | 落地页正常渲染, 无白屏/报错                                                                | ☐    |
| U2  | 游客看课程              | 点「开启学习」→ 课程广场                             | 看到已导入课程包; 顶部引导条显示「登录」                                                   | ☐    |
| U3  | 登录                    | 点登录 → Logto 完成登录 → 回到 `/callback`           | 登录成功并跳回应用; 刷新后仍为登录态                                                       | ☐    |
| U4  | 首次登录落库            | 登录后查库 `select count(*) from users`              | 新增 1 条 users 影子记录 (upsert 生效)                                                     | ☐    |
| U5  | 会员状态                | 打开 `/membership`                                   | 显示「当前未开通会员」+ 方案列表(4 档)                                                     | ☐    |
| U6  | 方案展示                | 检查方案卡                                           | 价格/天数/权益来自 API; 「最划算」标记跟随每天成本; 永久方案单独强调「一次购买, 永久有效」 | ☐    |
| U7  | 免费课学习              | 课程广场 → 免费课程包 → 学习                         | 游客/非会员可直接作答并记录进度                                                            | ☐    |
| U8  | 会员课拦截              | 点击会员课程包                                       | 提示需要会员, 不泄露课程内容                                                               | ☐    |
| U9  | 支付方式                | `/membership` 支付方式区                             | 显示微信支付(扫码) (RC 渠道已开启)                                                         | ☐    |
| U10 | 下单 (不支付)           | 点某方案开通                                         | 出现支付面板(等待支付/二维码链接/倒计时); 订单落库 `pending`                               | ☐    |
| U11 | 订单超时                | 等 `order_expire_minutes`(默认 120 分钟, 可临时改小) | 订单转 `expired`, 页面提示订单已关闭并可重新购买                                           | ☐    |
| U12 | 会员生效 (本地绕过支付) | 后台授予会员: `POST /admin/memberships/grant`        | `/membership` 显示会员生效 + 有效期; 会员课可学习                                          | ☐    |
| U13 | 学习闭环                | 完成若干句子 → 复习/成长报告                         | 进度、完成记录、复习数据更新正确                                                           | ☐    |

## 2. 推广 / 佣金链路

先给用户 A 授予 **lifetime** 会员 (`POST /admin/memberships/grant`), 给用户 B 普通账号。

| #   | 步骤               | 操作                                                                  | 预期                                                                              | 通过 |
| --- | ------------------ | --------------------------------------------------------------------- | --------------------------------------------------------------------------------- | ---- |
| P1  | 非终身用户看推广页 | 用户 B 打开 `/partner`                                                | 说明需先开通终身会员, 给出会员方案入口                                            | ☐    |
| P2  | 终身用户申请       | 用户 A 打开 `/partner` → 申请                                         | 状态变 `pending`(审核中)                                                          | ☐    |
| P3  | 管理员审核         | 后台 `POST /admin/partners/:id/approve`                               | 状态变 `active`; 页面出现推广链接与推广码                                         | ☐    |
| P4  | 佣金展示           | A 的 `/partner`                                                       | 显示当前佣金比例(来自规则表) + 收益示例 + 5 种佣金状态说明                        | ☐    |
| P5  | 归因               | 用 A 的链接 `?ref=<code>` 打开站点 → 用 B 登录                        | `referrals` 新增 1 条, `referred_user_id`=B; 再点一次不覆盖                       | ☐    |
| P6  | 自邀请防护         | 用 A 自己的链接登录 A                                                 | 归因被拒 (self_referral), 不产生记录                                              | ☐    |
| P7  | 佣金生成           | 让 B 产生一笔已支付订单(本地可用后台授予+手工置 paid, 或商户环境支付) | `commission_records` 1 条 `holding`, `hold_until ≈ paid_at + refund_window_hours` | ☐    |
| P8  | 保护期内退款       | 对该订单执行后台退款                                                  | 订单 `refunded`; 会员权益撤销; 佣金 `reversed`                                    | ☐    |
| P9  | 续费佣金           | B 再产生第二笔已支付订单                                              | 新增第 2 条佣金 (同一推广关系继续有效)                                            | ☐    |
| P10 | 永久会员佣金       | B 购买 lifetime 订单                                                  | 该订单仅 1 条佣金; 重复回调不新增                                                 | ☐    |
| P11 | 佣金结算           | 后台 `POST /admin/commissions/confirm` → `:id/payable` → `:id/settle` | 状态依次 `holding→pending→payable→paid`; 非法跳转被拒                             | ☐    |

## 3. 后台运营路径

需管理员 Logto 账号具备 `admin:access` scope。

| #   | 步骤     | 操作                                                                     | 预期                                                    | 通过 |
| --- | -------- | ------------------------------------------------------------------------ | ------------------------------------------------------- | ---- |
| A1  | 权限边界 | 普通用户访问 `/admin/plans` 的接口                                       | 返回 **403** (不是 200, 也不是 401)                     | ☐    |
| A2  | 方案管理 | `/admin/plans`: 改名/改价/下架/上架                                      | 前端会员页价格随之变化; 下架方案无法下单                | ☐    |
| A3  | 支付渠道 | 同上页面「支付渠道」区                                                   | 显示 enabled/configured; 开关可切换; **不出现任何密钥** | ☐    |
| A4  | 商业参数 | 同上页面「商业参数」区                                                   | 可改退款保护期/订单超时等; 非法值被拒 (400)             | ☐    |
| A5  | 佣金规则 | `GET/PATCH /admin/commission-rules`                                      | 可改比例(0–10000bps); 改后新订单用新比例, 历史佣金不变  | ☐    |
| A6  | 订单对账 | `GET /admin/orders?status=refunding`、`POST /admin/orders/:id/reconcile` | 异常订单可查询并可一键恢复                              | ☐    |
| A7  | 财务看板 | `/admin/dashboard`                                                       | GMV/退款/净收入/会员增长/佣金状态与库中数据一致         | ☐    |
| A8  | 课程运营 | `/admin` 课程包管理 + 内容管理                                           | 可创建/编辑/发布课程与句子; 发布后商城立即可见          | ☐    |
